# TradingHero 鬼点子生成器 v2 产品规格设计稿

## 1. v2 要解决什么问题

v1 已经能根据历史活动数据生成稳健、冲刺、互动三类方案，但生成结果偏“历史复用”，玩法容易收敛到秒杀、阶梯价、二选一、抽奖、加赠月数。v2 要把系统升级成一个更完整的直播营销策划工作台：

- 既能参考历史数据，做相对稳的方案。
- 也能不参考历史数据，扩散生成更好玩的直播互动玩法。
- 能根据活动日期、时令、节点、TradingHero 用户画像推荐礼品。
- 能建设一个可维护礼品库，作为前端和 skill 的共同基础数据。
- 能自动从 PDF 脑图中抽取历史出现过的礼品，并允许手动修正成本和市场参考价。

v2 的目标不是让系统完全自动决策，而是让你每周策划时先拿到 3-5 个有结构、有预算、有历史依据或市场灵感的可选方案。

## 2. v2 核心新增能力

### 2.1 生成模式

新增字段：`是否参考历史活动数据`

建议前端用分段控件，提供三种模式：

1. `参考历史`
   - 使用 v1 逻辑。
   - 优先历史高 GMV、高销量玩法。
   - 输出必须引用历史对照案例。
   - 适合需要稳妥、可解释、可预估的活动。

2. `不参考历史`
   - 不被历史玩法限制。
   - 允许扩散直播互动玩法、市场流行玩法、节日礼品创意。
   - 仍要受价格、预算、用户画像约束。
   - 预测 GMV 时必须标注“创意方案，历史置信度低”。

3. `混合模式`
   - 推荐默认模式。
   - 用历史数据确定成交逻辑，用市场玩法做包装创新。
   - 例如：历史证明“低价+限时+稀缺”有效，玩法包装可以换成“交易好运签”“行情能量补给站”“指标闯关”。

### 2.2 活动日期驱动

活动日期不只是记录字段，而要影响方案生成。

输入字段：

- 活动日期。
- 是否节日/大促节点。
- 是否月底/季度末/年末。
- 是否行情事件夜，例如 CPI、非农、美联储、期货重要数据。
- 是否新品/功能上线节点。

自动推断：

- 季节：春夏秋冬。
- 月份：月初、月中、月底。
- 节点：618、双11、双12、春节、元宵、端午、中秋、国庆、年末复盘。
- 用户状态：临期续费、试用转化、老用户召回、新用户教育。

日期影响：

- 玩法主题。
- 礼品类型。
- 福利力度。
- 是否适合冲 GMV。
- 是否适合前置蓄水。
- 是否适合返场收割。

### 2.3 礼品库

新增一个结构化礼品库，作为生成器的重要输入。

礼品库用途：

- 为方案提供可选礼品。
- 计算礼品成本是否超预算。
- 区分实际成本和用户感知价值。
- 让前端支持手动新增、编辑、禁用、标记库存。
- 给 skill 提供礼品推荐依据。

### 2.4 PDF 礼品抽取

从历史 PDF 脑图中自动抽取出现过的礼品，生成礼品候选表。候选表不直接进入正式礼品库，先进入“待确认”状态。

抽取目标：

- 礼品名称。
- 出现月份。
- 出现活动。
- 上下文玩法。
- PDF 中是否出现价格。
- 是否可能是虚拟权益或学习资料。
- 是否需要人工确认。

### 2.5 市场灵感来源

当选择“不参考历史”或“混合模式”时，系统可使用外部市场信息源。v2 先设计信息源规范，不要求一开始自动联网。

可用来源：

- 电商平台商品价格：京东、淘宝、天猫、拼多多。
- 内容平台趋势：抖音、视频号、小红书、B站。
- 直播电商数据平台：蝉妈妈、飞瓜数据、新榜、灰豚等。
- 公司内部资料：历史 PDF 脑图、Excel 真实活动记录、客服反馈、销售复盘。
- 人工维护礼品库：你手动设置的市场价、成本价、库存状态、用户感知价值。

v2 原则：

- 市场来源用于“创意”和“价格参考”。
- 历史 Excel 数据用于“效果依据”。
- 外部趋势不能直接替代 TradingHero 历史成交数据。

## 4. 0 元成本礼品规则

你明确提到这些礼品目前有库存，不用再生产，因此不占用活动礼品经费：

- 好用的指标手册
- 黄金手机贴
- 马年钥匙扣
- 订单流桌垫
- 黄金知识桌垫

默认入库规则：

- `actual_cost = 0`
- `budget_cost = 0`
- `is_inventory = true`
- `is_zero_budget = true`
- `stock_status = 充足`，除非你手动改成有限或缺货
- `category = 学习资料` 或 `实物`
- `source_type = 内部库存`

使用规则：

- 这些礼品可作为“免费叠加福利”，提升方案厚度。
- 不计入用户设置的福利预算。
- 不能把它们当成主要成交理由，除非和价格、名额、课程或权益绑定。
- 输出方案时要写清：这些是库存权益，不占用本次礼品预算。

## 5. 活动日期与礼品推荐规则

### 5.1 按季节

春季：

- 办公焕新、学习工具、桌垫、手册、计划本、课程权益。
- 适合主题：春日开工、交易计划、指标学习。

夏季：

- 挂脖风扇、冰感杯、便携水杯、防晒用品、清凉办公小物。
- 适合主题：夏日补给、行情清凉包、交易能量站。

秋季：

- 中秋礼盒、茶饮、养生壶、办公靠垫、收纳用品。
- 适合主题：秋季复盘、稳健交易、丰收礼。

冬季：

- 暖手宝、保温杯、加热坐垫、年货礼盒、台历、复盘资料。
- 适合主题：年末复盘、新年计划、开门红。

### 5.2 按节点

月初：

- 适合学习、计划、目标启动。
- 礼品偏课程、手册、桌垫、计划工具。

月中：

- 适合普通转化和互动增强。
- 礼品偏实用小物、E 卡、抽奖资格。

月底：

- 适合冲刺、限时、名额、阶梯福利。
- 礼品偏强感知、大奖池、加赠月数、限名额权益。

行情夜：

- 适合指标资料、订单流资料、内部直播课、短线实战课。
- 礼品应更贴近交易场景，少送泛生活礼品。

重大促销：

- 可用大奖池、稀缺名额、阶梯价、二选一、预购返场。

## 6. TradingHero 用户画像礼品偏好

目标人群大概率更看重：

- 交易效率：指标、订单流、盘外价、行情工具。
- 学习提升：手册、课程、内部直播、复盘资料。
- 办公实用：桌垫、便携屏、键鼠、支架、充电宝。
- 交易仪式感：黄金摆件、好运签、台历、交易计划工具。
- 可感知价值：京东 E 卡、实用小电器、行李箱、显示屏。

不建议优先：

- 和交易场景完全无关、解释成本高的礼品。
- 成本高但用户感知弱的礼品。
- 需要复杂物流、售后或尺码选择的礼品。
- 容易让用户只关注抽奖、不关注购买理由的礼品。

## 7. 直播玩法库设计

v2 需要把玩法拆成“成交逻辑”和“互动包装”。

成交逻辑：

- 低价秒杀
- 阶梯价
- 前 N 名
- 限时倒计时
- 预购抵扣
- 返场收割
- 加客服锁名额
- 课程转化

互动包装：

- 礼品二选一
- 盲盒墙
- 刮刮乐
- 砸金蛋
- 转盘
- 好运签
- 双主播叠加福利
- 弹幕投票换礼品
- 闯关解锁福利
- 行情任务卡

生成原则：

- 历史模式：优先使用历史验证过的成交逻辑。
- 创意模式：可以大胆换互动包装。
- 混合模式：成交逻辑用历史强项，互动包装用新玩法。

- `zero_budget_gifts_allowed = true`
- `market_creativity_level = 中等`

## 11. PDF 礼品抽取流程

第一步：从 PDF 文本中提取候选礼品。

识别线索：

- “礼品”
- “加赠”
- “二选一”
- “三选一”
- “抽奖”
- “京东 E 卡”
- “便携屏”
- “行李箱”
- “黄金”
- “桌垫”
- “手册”
- “台历”
- “投影仪”
- “电视”

第二步：清洗候选礼品。

- 去重。
- 合并同义词。
- 分离礼品和玩法词。
- 提取价格。
- 标记是否需要人工确认。

第三步：生成候选表。

字段：

- 礼品名称
- 来源 PDF
- 出现月份
- 上下文活动
- 价格文本
- 初步分类
- 建议成本
- 是否 0 元库存候选
- 置信度
- 人工确认状态

第四步：人工确认入库。

- 确认名称。
- 设置成本价。
- 设置市场价。
- 设置是否占用预算。
- 设置是否库存礼品。

## 12. 外部市场信息获取方案

v2 先做“人工/半自动”，后续再做“联网自动”。

### v2 手动方案

- 运营人工在京东/淘宝搜索商品价格。
- 人工录入礼品库。
- skill 使用礼品库，不直接联网。

优点：稳定、可控、不会抓错价格。  
缺点：需要维护。

### v2.5 半自动方案

- 输入礼品名称。
- 系统生成搜索关键词。
- 人工打开京东/淘宝/小红书/抖音搜索。
- 复制价格或链接回礼品库。

优点：减少整理成本。  
缺点：仍需人工确认。

### v3 自动方案

- 连接商品搜索 API 或爬取工具。
- 定期更新市场价。
- 自动标记价格波动。

优点：自动化高。  
缺点：维护复杂，可能遇到反爬、价格不稳定、链接失效。

## 14. 实施顺序

推荐下一步这样做：

1. 先创建礼品库 v1。
   - 手动录入 0 元库存礼品。
   - 从 PDF 抽取候选礼品。
   - 人工确认前 30-50 个高频礼品。

2. 更新 skill 到 v2。
   - 增加 `参考历史 / 不参考历史 / 混合模式`。
   - 增加日期/时令规则。
   - 增加礼品库使用规则。
   - 增加市场创意模式。

3. 做 5 个测试场景。
   - 参考历史模式。
   - 不参考历史模式。
   - 混合模式。
   - 仅用 0 元库存礼品。
   - 指定活动日期和季节礼品。

4. 再设计前端页面。
   - 先做输入表单和方案输出。
   - 再做礼品库管理。
   - 最后做 PDF 抽取和市场价更新。

## 15. v2 不做的事情

- 不直接自动联网抓商品价格。
- 不自动购买礼品。
- 不把市场热度当成 GMV 预测依据。
- 不把 PDF 脑图中的礼品直接视为可用库存。
- 不用创意模式替代历史效果模式。
- 不保证所有市场玩法适合 TradingHero 用户。

## 16. 验收标准

v2 设计落地后，应能通过这些测试：

1. 输入：参考历史，售价 2690，预算 100-150，目标冲 GMV。  
   期望：生成历史验证型方案，引用强折扣、阶梯价、加赠月数案例。

2. 输入：不参考历史，活动日期 8 月，售价 2950，预算 150-200。  
   期望：生成更有创意的夏季互动玩法和清凉办公礼品，但预测标为低置信。

3. 输入：混合模式，月底，售价 2890，预算 200-300。  
   期望：成交逻辑使用历史强项，玩法包装有新意，并推荐大奖池或稀缺名额。

4. 输入：仅用 0 元库存礼品。  
   期望：方案使用指标手册、黄金手机贴、马年钥匙扣、订单流桌垫、黄金知识桌垫，并显示预算消耗为 0。

5. 输入：使用礼品库，预算 100-150。  
   期望：只推荐预算内礼品，不推荐超预算高价值实物，除非作为抽奖池。

6. 输入：PDF 抽取礼品。  
   期望：生成候选礼品表，并标记人工确认状态。
